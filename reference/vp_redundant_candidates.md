# Written requirements that follow from others

Candidate redundant constraints: written requirements ("a requires b")
that follow from a chain of other requirements. Give the constraints of
the model that you want to examine; each one that is not in the skeleton
is implied by others, and a solver can confirm that removing it changes
nothing.

## Usage

``` r
vp_redundant_candidates(model, written)
```

## Arguments

- model:

  A model, from
  [`vp_generate()`](https://rheradio.github.io/variplex/reference/vp_generate.md)
  or
  [`vp_read()`](https://rheradio.github.io/variplex/reference/vp_read.md),
  in its complete or its minimal form.

- written:

  A tibble with `from` and `to`: written requirements of the model.

## Value

The rows of `written` with `in_graphs` (the arrow holds), `redundant`
(it follows from others) and `via`.

## Examples

``` r
band <- vp_generate(vp_example("miband3.uvl"), or_graph = TRUE)
written <- data.frame(
  from = c("TouchScreen", "TouchScreen"),
  to = c("Screen", "OLED")
)
vp_redundant_candidates(band, written)
#> # A tibble: 2 × 5
#>   from        to     in_graphs redundant via   
#>   <chr>       <chr>  <lgl>     <lgl>     <chr> 
#> 1 TouchScreen Screen TRUE      TRUE      BLEv42
#> 2 TouchScreen OLED   TRUE      TRUE      BLEv42
```
